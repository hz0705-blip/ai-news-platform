# 골든셋은 동일 계열 두 모델 교차 검증과 단일 어노테이터로 만든다

평가 수치를 내려면 정답이 필요한데 어노테이터는 운영자 한 사람이다. 정답 초안은 OpenAI 상위 모델과 하위 모델이 독립 작성하고, 일치하는 항목은 정답으로 채택하며 불일치 항목만 운영자가 판정한다. 불일치율을 리포트에 남기고 "동일 계열 두 모델 교차 검증, 단일 어노테이터"라는 한계를 명시한다. 골든셋은 홀드아웃이며 파이프라인 개발 중 프롬프트 튜닝에 쓰지 않는다.

## 고려한 대안

- **운영자 전수 라벨링**: 1인 시간으로는 의미 있는 크기를 만들 수 없다.
- **다른 계열 모델과 교차**: 공급자 단일화([ADR-0005](0005-stack-a-and-single-openai-provider.md))와 충돌하고 비용 추적이 갈라진다. 같은 계열이라 상관된 오류를 놓칠 수 있다는 한계는 리포트에 적는다.
- **골든셋을 개발 중 튜닝에 사용**: 평가가 오염되어 수치를 믿을 수 없게 된다.

## 결과

- 데모 사건 4개의 정답이 첫 항목이고, M2a부터 실제 사건 패킷을 추가한다.
- 리뷰어는 리포트에서 수치와 함께 만든 방법과 한계를 읽는다. 수치를 얼마나 믿을지는 리뷰어가 정한다.
- 크기와 절차(2026-09-17, 리서치 #10 반영): 홀드아웃은 미공개 영어 사건 패킷 100개와 기사 쌍 약 300개다. 임계값·프롬프트 조정용 개발셋(패킷 20개, 쌍 60개)은 별도로 두고 홀드아웃과 겹치지 않는다. 데모 사건 4개는 회귀 픽스처로 남기고 성능 헤드라인에서 제외한다. 운영자는 불일치 항목 전부와 일치 항목의 무작위 20%, 수치·날짜·발언자 항목을 검토하며, 라벨 출처를 모델 합의 / 운영자 판정 / 운영자 감사로 구분해 기록한다. 리포트는 두 모델의 합의율·불일치율·기권율·카파와 각 지표의 분모를 적고, 신뢰 구간은 사건 패킷 단위 부트스트랩으로 낸다. 예산이 모자라면 실제 홀드아웃 수를 그대로 보고한다.
- CI는 결정론 검사와 기록된 응답 리플레이만 매 변경마다 돌리고 유료 모델을 호출하지 않는다. 홀드아웃 모델 평가는 마일스톤 종료 단위로 수동 실행한다. 커밋마다 돌리면 비용이 들고 비결정론적 출력이 거짓 실패를 만들며, 그 자체가 홀드아웃을 조정에 노출시키기 때문이다.
