# 상충 상태는 주장 개정판에 저장하고 사건 상태는 파생한다

상충 상태(단일 출처 / 복수 출처 일치 / 보도 상충 / 상충 해소 / 정정됨)는 각 주장의 개정판에 저장한다. 사건 개정판의 상태는 현재 주장들의 상태와 아직 닫히지 않은 상충 에피소드에서 같은 트랜잭션 안에 결정론적 규칙으로 파생한 스냅샷이며, 따로 편집하는 필드를 두지 않는다. 핵심 feature가 "어느 문장이 왜 상충인가"를 보여주는 것이므로 상태의 권위는 주장에 있어야 하고, 사건 배지는 그 집계여야 한다. 상태는 순서가 정해진 워크플로가 아니라 재평가마다 우선순위 가드로 다시 계산되는 상태 기계다. 모델은 근거 사이의 관계를 라벨하고, 최종 상태 값은 규칙이 정한다.

## 고려한 대안

- **사건 수준에만 저장**: 구조가 단순하지만 어느 주장이 상충인지 화면에서 보여 줄 수 없어 상충 주장 비교 feature가 약해진다.
- **주장과 사건에 각각 독립 저장**: 두 값이 어긋날 수 있고, 리플레이 테스트로 재현할 수 없다.
- **과거 정정이 사건 배지를 영구 지배**: 오래된 사건의 배지가 동결되고 새 상충과 과거 정정이 경쟁한다. 대신 정정됨·상충 해소는 해당 주장이 현재 요약에 있는 동안만 배지를 지배하고, 과거 정정은 변화 이력에 남긴다.
- **요약에서 빠진 주장의 상충을 무시**: 요약 편집으로 상충이 숨겨진다. 대신 열린 상충 에피소드는 주장이 요약에서 빠져도 명시적으로 닫힐 때까지 사건 상태에 남는다.

## 결과

- 수동으로 상태를 "전진"시키는 조작이 없다. 사건은 단일 출처 → 보도 상충, 정정됨 → 보도 상충, 상충 해소 → 복수 출처 일치, 복수 출처 일치 → 단일 출처 어디로든 근거가 바뀌면 이동한다.
- 상충 에피소드는 명시적 철회·정정·해소 또는 운영자의 오분류 정정으로만 닫힌다. 침묵, 시간 창 만료, 본문 삭제, 요약 제외로는 닫히지 않는다.
- 발행할 수 없는 상태(독립 원점 0, 검증 누락, 판정 불가)는 이전 상태를 유지하고 운영 상태로 따로 표시한다. 여섯째 상태 값이나 신뢰 점수를 추가하지 않는다([ADR-0004](0004-no-bias-or-confidence-scores.md)).
- 파생 규칙과 전이 가드는 결정론 픽스처로 테스트하며 M1 인수 조건이다. 세부 가드는 `docs/spec/v1.md` "도메인 모델 규칙"의 상충 상태 항목이 정본이다.
