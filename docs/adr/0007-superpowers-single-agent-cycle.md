# 구현 티켓은 Claude 컨트롤러가 티켓 생성부터 자동 머지까지 사람 개입 없이 돌리고, 리뷰는 PR당 1회, Codex는 리서치만 맡는다

목표는 제품 완성이다. 구현 → 테스트 → 리뷰 → 머지를 사람이 경계마다 큐를 넘기지 않고 한 사이클로 돌리기 위해, Claude Code 컨트롤러가 스펙 마일스톤에서 티켓을 만들고, `ready-for-agent` 큐를 번호순으로 순회하며, 티켓마다 구현 서브에이전트 하나와 리뷰 서브에이전트 하나로 PR을 만들어 CI 초록이면 머지한다. Codex는 `research` 이슈만 맡고 저장소를 바꾸지 않는다. superpowers는 SessionStart 훅의 `using-superpowers` 주입으로만 남고, 그 본문이 CLAUDE.md 우선을 명시하므로 스킬 원문과 다른 규칙은 `CLAUDE.md`에 두고 값은 `docs/agents/project.md`에 둔다.

12개 PR(#14~#25)과 그 사이 절차 개정 3회(#45, #46, 이번)의 실측으로 사이클을 다음과 같이 고정한다(2026-09-27 2차 개정. 이 ADR은 이전의 0011 서브에이전트 모델 티어, 0012 리뷰 게이트 차등, 0013 UI 티켓 통합을 흡수했다. 원문은 git 이력).

1. **워크트리를 쓰지 않는다.** 동시 구현이 없으므로 메인 체크아웃의 `ticket/<이슈>-<slug>` 브랜치로 충분하다.
2. **분류는 민감 여부 하나.** 마이그레이션·시크릿·인증·백업·복구를 건드리면 민감: 구현자·리뷰어 fable, 머지 전 사용자 승인. 그 밖은 구현자·리뷰어 opus, 자동 머지.
3. **계획 파일·원장·SDD를 쓰지 않는다.** 컨트롤러가 이슈 본문에 파일 후보·테스트 이름 몇 줄을 보태 구현자 프롬프트로 준다. 계획 파일은 #23에서 1,300줄까지 갔고 교차 리뷰 지적의 절반이 계획 코드 자체의 오류였다. 작은 티켓(#19, #25)에서 브리프 추출·원장·이관은 순수 오버헤드였다.
4. **구현자는 티켓 하나를 끝까지.** 태스크 수·줄 수 상한이 없다. 한 번에 못 끝내면 같은 브랜치에서 이어받는 구현자를 최대 2회. 티켓 크기는 컨트롤러가 티켓을 만들 때 "구현자 한 명이 한 번에" 기준으로 자른다.
5. **리뷰는 PR당 1회.** 리뷰 서브에이전트 하나가 동작·인수 조건·명백한 결함만 본다. Critical/Important만 수정 1회, 재검토 없음. 12개 PR에서 리뷰 반영 커밋은 PR당 1~4개로 대부분 유효했으나, 계획 교차 리뷰·태스크 리뷰·최종 리뷰·2축 `/code-review`는 같은 결함을 겹쳐 잡았다. Codex 계획 교차 리뷰를 폐지한다.
6. **자동 머지.** 비민감 티켓은 CI 초록 + 리뷰 Critical 없음이면 컨트롤러가 승인 없이 스쿼시 머지한다. PR은 CI 게이트·스쿼시 단위·"무엇을 남겼나" 기록을 묶는 단위로 남긴다. 티켓 자체는 당일 끝났는데 다음 착수가 머지 승인에 걸렸다.
7. **Ruling은 정하고 기록한다.** 묻는 것은 ADR 충돌뿐. 138개 스펙 결정 항목이 구현마다 티켓 코멘트 왕복을 만들었다. 문서를 바꾸는 Ruling은 같은 PR에 넣고 머지가 편집 승인을 겸한다.
8. **큐 순회.** 머지 뒤 `ready-for-agent`·차단 없음·번호 오름차순으로 다음 티켓을 바로 착수한다. 큐가 비거나 blocked일 때만 멈춘다.
9. **티켓 생성·분류를 컨트롤러가 한다.** `/to-tickets`·`/triage`가 사용자 전용이어서 큐 채우기가 사람에게 걸렸다. 사용자는 이슈 목록을 훑고 배포 화면을 본다.
10. **UI 티켓도 같은 사이클.** ui-skills 원문은 `docs/ui-skills/`에 커밋돼 있다.
11. **플러그인 버전 게이트를 두지 않는다.**
12. **절차 문서 동결.** 이 ADR·`CLAUDE.md`·`project.md` "사이클 값"은 M6까지 고치지 않는다. main 커밋 44건 중 문서·절차가 34건으로 기능 10건의 세 배였고, 절차를 고치는 일 자체가 가장 큰 낭비였다.

## 고려한 대안

- **역할 분담(Claude 계획·리뷰, Codex 구현)**: 경계마다 사람이 두 도구 사이 큐를 넘겨야 한다.
- **superpowers 원문 그대로**: brainstorming이 스펙과 별도의 설계 문서를 만들고, park·complete가 미해결 Critical을 안고 넘어가며, 워크트리를 강제한다.
- **리뷰 전면 폐지, CI만**: CI가 유일한 안전망이 된다. 리뷰 1회는 사람 시간이 들지 않으므로 남긴다.
- **PR 없이 main 직접 push**: CI 게이트와 변경 단위 기록을 잃는다. 자동 머지면 PR의 사람 비용은 0이다.
- **다섯 겹 리뷰·계획 교차 리뷰 유지**: 실측에서 중복이었다.

## 결과

- 사람의 판단 지점은 스펙 개정 승인, 민감 티켓 머지 승인, 배포 화면 확인 셋이다. 증거 경로는 티켓 → PR 본문 "무엇을 남겼나" → 리뷰 코멘트.
- 재검토 조건은 하나: 머지 뒤 되돌린 PR이 연속 2건이면 리뷰 회차를 늘린다. 그 밖의 절차 변경은 M6까지 하지 않는다.
