# 서브에이전트 모델은 태스크 등급으로 고정한다

superpowers subagent-driven-development는 구현자·리뷰어 모델을 브리프마다 명시하라고 하면서 티어는 fast/standard/most-capable라는 추상 명칭으로만 둔다. #14~#18 다섯 사이클에서 모델은 사이클마다 즉흥으로 골랐고, #18에서는 haiku 구현자가 커밋 트레일러를 자기 모델명으로 찍어 amend가 필요했다. 이 ADR은 태스크 등급 세 개(light·standard·heavy)와 역할별 모델 표를 `docs/agents/project.md` "서브에이전트 모델"에 두고, 등급을 writing-plans 단계에서 계획 파일 태스크 헤더에 적어 SDD가 그대로 쓰게 한다. 최상위 티어는 Opus 5, 비밀·인증·백업·복구·마이그레이션을 건드리는 민감 티켓의 최종 리뷰만 Fable 5.1이다. 수정 4~5회차는 한 티어 위로 간다.

## 고려한 대안

- **항상 Fable 5.1로 최종 리뷰**: SDD의 "가장 유능한 모델" 문구를 그대로 따르지만 비용이 가장 크다. 민감 티켓에만 쓴다.
- **항상 Opus 5 상한**: 가장 저렴하지만 데이터 손실·비밀 노출 위험이 있는 티켓의 리뷰 강도가 낮다.
- **`.claude/agents/*.md`에 모델을 고정한 커스텀 에이전트**: superpowers 프롬프트 템플릿과 이중화된다. 브리프 표준 문구로 트레일러 문제가 해결되지 않으면 재검토.

## 결과

- 계획 파일 `### Task N:` 아래 첫 줄이 `**모델:** light|standard|heavy`. SDD가 등급을 바꾸면 원장에 Ruling으로 남긴다.
- 브리프 첫 블록은 `project.md` "브리프 표준 문구"(트레일러·테스트 명령·보고 형식).
- 재검토 조건: Claude 모델 라인업 변경, 등급별 수정 회차 통계(light 태스크가 2회 이상 수정을 반복하면 등급 기준을 올린다).
- 실측 1건(#19, 2026-09-20): 파일 3개·255줄, 태스크 2개(standard 구현 sonnet, light 문서 haiku), 태스크 리뷰 둘 다 sonnet, 최종 리뷰 fable("마이그레이션" 키워드로 민감 티켓 판정). 수정 회차 0, 최종 리뷰 Critical·Important 0(Minor 5건은 #36으로). 트레일러 문제도 재발하지 않았다. 표는 그대로 둔다. 다만 근거가 이 한 건뿐이고 heavy 태스크와 민감하지 않은 티켓의 최종 리뷰는 아직 실측이 없어, 다음 두세 사이클까지는 여전히 잠정이다.
