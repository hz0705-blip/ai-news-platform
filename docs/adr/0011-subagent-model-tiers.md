# 서브에이전트 모델은 태스크 등급으로 고정한다

superpowers subagent-driven-development는 구현자·리뷰어 모델을 브리프마다 명시하라고 하면서 티어는 fast/standard/most-capable라는 추상 명칭으로만 둔다. #14~#18 다섯 사이클에서 모델은 사이클마다 즉흥으로 골랐고, #18에서는 haiku 구현자가 커밋 트레일러를 자기 모델명으로 찍어 amend가 필요했다. 이 ADR은 태스크 등급 세 개(light·standard·heavy)와 역할별 모델 표를 `docs/agents/project.md` "서브에이전트 모델"에 두고, 등급을 writing-plans 단계에서 계획 파일 태스크 헤더에 적어 SDD가 그대로 쓰게 한다. 2026-09-23 사용자 결정으로 표를 올렸다: light·standard 구현자와 리뷰어는 Opus 5, heavy 구현자·리뷰어와 모든 최종 리뷰는 Fable 5.1. 수정 4~5회차는 opus → fable. 서브에이전트 단가보다 결과 품질을 우선한다는 것이 이유이며, 호출 횟수는 ADR-0012의 리뷰 게이트 차등으로 줄인다.

## 고려한 대안

- **haiku/sonnet/opus 3단 표(2026-09-19 초판)**: 가장 저렴했으나 #18에서 haiku 구현자의 트레일러 오류가 있었고 #22 진행 중 사용자가 기본 상향을 지시했다.
- **항상 Fable 5.1**: 품질은 최대지만 light 태스크(문서·설정)에는 과하다.
- **`.claude/agents/*.md`에 모델을 고정한 커스텀 에이전트**: superpowers 프롬프트 템플릿과 이중화된다. 브리프 표준 문구로 트레일러 문제가 해결되지 않으면 재검토.

## 결과

- 계획 파일 `### Task N:` 아래 첫 줄이 `**모델:** light|standard|heavy`. SDD가 등급을 바꾸면 원장에 Ruling으로 남긴다.
- 브리프 첫 블록은 `project.md` "브리프 표준 문구"(트레일러·테스트 명령·보고 형식).
- 재검토 조건: Claude 모델 라인업 변경, 등급별 수정 회차 통계(light 태스크가 2회 이상 수정을 반복하면 등급 기준을 올린다), ADR-0012 게이트 차등 뒤에도 사이클당 서브에이전트 비용이 줄지 않으면 light를 sonnet으로 내린다.
- 실측 1건(#19, 2026-09-20): 파일 3개·255줄, 태스크 2개(standard 구현 sonnet, light 문서 haiku), 태스크 리뷰 둘 다 sonnet, 최종 리뷰 fable("마이그레이션" 키워드로 민감 티켓 판정). 수정 회차 0, 최종 리뷰 Critical·Important 0(Minor 5건은 #36으로). 트레일러 문제도 재발하지 않았다. 표는 그대로 둔다. 다만 근거가 이 한 건뿐이고 heavy 태스크와 민감하지 않은 티켓의 최종 리뷰는 아직 실측이 없어, 다음 두세 사이클까지는 여전히 잠정이다.
