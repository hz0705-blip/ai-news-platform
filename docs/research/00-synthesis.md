# 리서치 취합 — 인터뷰용 (2026-09-15)

Codex 리서치 5건(`docs/research/01~05`)을 Claude가 취합한 문서. **모든 내용은 리서치 권고이며 결정이 아니다.** 결정은 `/grill-with-docs` 인터뷰에서 내리고 ADR로 기록한다.

> 상태: 5개 문서 모두 반영 완료 (01 시장 · 02 UX · 03 스택 · 04 AI 파이프라인 · 05 포트폴리오 기준).

## 1. 다섯 문서가 한목소리로 말하는 것

1. **요약·묶음·개인화만으로는 차별화가 안 된다.** Ground News, Particle, 네이버가 이미 조합해 제공한다. (01)
2. **핵심 제품 가설은 "근거를 확인할 수 있는 사건(Story) 페이지 + 마지막으로 읽은 이후 무엇이 바뀌었나".** 01·02·04가 독립적으로 같은 결론에 도달했다.
3. **정치 편향 점수는 보류.** 미국 좌우 프레임(Ground)을 한국에 이식하면 안 되고, 검증된 한국 루브릭 없이는 출처·지역·언어·근거 차이만 보여준다. (01·02·04)
4. **신뢰는 점수가 아니라 검사 가능한 근거로.** 요약 문장마다 원문 구간 연결, "단일 출처", "보도 상충", "정정됨" 같은 상태 표시. 숫자 확신도는 쓰지 않는다. (02·04)
5. **데이터 권리가 최대 리스크.** 네이버 검색 API는 2026-09-07 약관으로 AI 입력이 금지됨. 한국 언론사 RSS는 개인 비상업용. 공개 포트폴리오라도 예외가 아니다. (04)
6. **"진짜 프로덕트"의 증거는 평가 리포트와 운영 지표.** 골든셋, 인용 정합성, 클러스터링 ARI/NMI, 비용/지연 대시보드를 저장소에 남긴다. (04, 05 예정)

### 2-5. AI 파이프라인 (04)

- 순서: 정확 중복 제거 → 다국어 임베딩 → 온라인 사건 배정(베이스라인) → 근거 문장 추출 → 요약·검증. HDBSCAN/응집형은 오프라인 비교용.
- 모델 후보(벤치마크 대상, 순위 아님): 저가 호스티드(`gpt-5.6-luna` $0.20/$1.20, Gemini 3.5 Flash-Lite, Claude Haiku 4.5) 기본 + Sonnet 5 샘플 검증. 셀프호스트 Qwen3.5-9B는 비교용.
- 임베딩 후보: BGE-M3, Qwen3-Embedding-0.6B, `text-embedding-3-small`, 한국어 파인튠 bge-m3-korean.
- 비용 가정: **하루 1천 건 약 $105/월, 5천 건 약 $500/월**(모델만, 라이선스·인프라 제외).
- 평가: 300 사건 패킷 골든셋(한/영/혼합 각 100) + 어려운 기사쌍 1,000. 지표: 요약 충실도, 인용 정합성(100% 유효 span은 결정론 게이트), 커버리지, 클러스터링 ARI/NMI, 입장/개체 F1, p50/p95 지연·건당 비용. LLM 심판은 위치·장황함 편향 통제.

### 2-6. 기술 스택·아키텍처 (03)

공통 베이스라인: Node 24 LTS, TypeScript 6, PostgreSQL 17/18 + pgvector 0.8, Drizzle, pg-boss(잡 큐), Postgres FTS, 오브젝트 스토리지, Supabase Auth. 웹과 워커는 별도 프로세스.

|---|---|---|---|---|
| **A — React 단일 언어** (03 권고) | Next.js 16 + React 19, 라우트 핸들러/액션, Node 워커가 호스티드 AI 호출 | 공개 콘텐츠·리더 UI·수집이 TS 도메인 모듈을 공유. Python 없이도 평가·검색으로 AI 증거 확보 | 프레임워크 캐싱·서버/클라이언트 경계 학습 필요 | $90–180 |

- **아키텍처**: 모듈형 모놀리스 + 별도 워커. 수집 파이프라인은 단계별 재시도·중복 방지·버전 기록, 검증된 분석만 발행. 소스 사실·파생 분석·번역은 분리 버전 관리.
- **검색**: Postgres FTS를 좁은 인터페이스 뒤에. 한국어는 별도 평가 후 Meilisearch/Typesense 검토.
- **인증**: 한국은 Kakao, 글로벌은 Google/GitHub. 익명 읽기 우선.
- **B로 승격 조건**: "이름 붙일 수 있는 ML 능력"이 있을 때만. LLM 요청을 전달만 하는 Python 서비스는 오히려 감점 요인.
- **제출용 증거 5개**: 수집 리플레이(멱등성), 한/글로벌 검색 비교, 비용 포함 분석 품질 리포트, 복구 연습, 배포/롤백 시연.
- 예산은 뉴스 이용료·세금·GPU 제외.

| 진입점 | README 1개 + 직무별 읽기 경로 2개 | 별도 내러티브 사이트 | 증거 베이스 하나, 요약만 공고별로 |

- **리뷰 게이트 3단계**: ① 신뢰할 수 있는 데모(권리 픽스처, 익명 여정, 비용 제한, 상태·메타데이터, 개인정보·출처 표기, 외부 스모크 모니터링) → ② 방어 가능한 엔지니어링(재현 가능 셋업, 다이어그램 1장, ADR·이슈 이력, 복구/롤백 연습, 방법 표기된 성능) → ③ 방어 가능한 AI(버전 관리된 홀드아웃 평가, 베이스라인 비교, 언어/토픽별 실패 슬라이스, 비용·지연, 회귀 사례).
- **성능 목표**: LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1. 실측 전엔 달성 주장 금지.
- **직무별 표현**: 한국 지원은 문제/행동/결과/배움 + 개인 기여. 글로벌은 같은 증거를 영어로, 공고 책임에 맞춰. AI/ML은 평가 리포트를 데모 옆에, 풀스택은 유저 플로우·통합 증거를 앞에.
- **흔한 실패**: 미완성 기능, 테스트 없음, 죽은 데모, 튜토리얼 클론, "왜"가 없는 README.

## 3. 브리프 간 긴장 지점

- **01 "한국어 우선" vs 04 "한국 소스 권리 막힘"**: 한국어로 가려면 정책브리핑·자체 픽스처·계약 중 하나가 필요. 영어 소스(Wikinews, Guardian 계약)로 시작하고 한국어 UI를 얹는 절충이 가능.
- **02 "게스트 우선" vs 01 "이어읽기·변화 추적"**: 변화 추적은 읽은 상태 저장이 필요 → 익명 로컬 상태로 시작할지, 계정을 1차에 넣을지 결정 필요.
- **포트폴리오 데모 vs 실제 서비스**: 라이브 커버리지 넓히면 권리·비용이 커진다. 큐레이션된 데모 코퍼스 + 라이브 소량이 현실적.

## 4. 인터뷰에서 결정할 것 (프론티어 1라운드 후보)

1. **첫 사용자와 언어**: 한국 일반 독자 / 한국 전문가의 해외 이슈 / 영어권. 혼합 소스 요약은 어느 언어로?
2. **핵심 반복 과업**: 5분 브리핑 / 상충 주장 비교 / 진행 중 사건의 변화 추적. 화면이 좁을 때 무엇이 남는가?
3. **성격과 예산**: 포트폴리오 데모 / 무료 공개 서비스 / 유료 가능성. 월 운영·데이터 라이선스 예산 상한.
4. **데이터 전략**: 큐레이션된 권리 확보 코퍼스로 시작 가능한가, 아니면 광범위 라이브 커버리지가 필수인가? 초기 카테고리와 소스 셋.
5. **정치 편향 표시 여부**: 한다면 누가 한국 루브릭을 승인·유지하는가?
6. **이중언어 범위**: UI 현지화만 / 번역 요약 / 실제 교차언어 소스 비교.
7. **계정·상태**: 익명으로도 유용해야 하나? 개인화 데이터 수집 범위.
8. **신선도**: 분 / 시간 / 일간. 백필·평가는 배치로 가능한가?
9. **성공 기준**: 재방문 / 변화 정확 회상 / 근거 검증 성공 / 지불 의향.
10. **사람 검수**: 주당 검수 시간, 2차 한/영 어노테이터 확보 가능성, 정정·삭제 처리 주체.
11. **접근성·기기 하한**: WCAG 2.2 AA, 한국 인앱 브라우저 지원 범위.
12. **스택 세트**: A(Next.js 단일) / B(+FastAPI) / C(SvelteKit). Python 서비스를 정당화할 "이름 붙일 수 있는 ML 능력"이 있는가?

15. **공개 가능 범위**: 실패한 실험, 측정 결과, AI 도구 사용 내역을 포트폴리오 증거로 공개할 의향.
